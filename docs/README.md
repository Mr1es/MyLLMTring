### 两篇重点文档的分工

**[`startup.md`](./startup.md) —— 面向「现在要把它跑起来」**

操作手册。启动前置、六个步骤的检查目标、故障排查顺序。

**[`bubble-fix-handoff.md`](./bubble-fix-handoff.md) —— 面向「想知道它为什么曾经跑不起来」**

事故复盘。核心是那条协议铁律的来历：
`response.output_item.added` 的 `arguments` 必须是真空串 `''`，
否则上游 Cortico 框架的增量累加校验会失败、把整条流判为 aborted，
工具永不执行——表现就是「桌宠没有气泡」，且服务端日志无报错，极难定位。

> 只想解决眼前问题 → 读 `startup.md`
> 想理解设计约束为什么长这样、避免改坏 → 读 `bubble-fix-handoff.md` + [`../shim/README.md`](../shim/README.md)
